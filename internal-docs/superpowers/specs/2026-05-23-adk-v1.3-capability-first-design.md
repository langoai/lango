# ADK v1.3 Capability-First Integration — Design Spec

- **Date:** 2026-05-23
- **Branch:** `feature/adk-v1.3`
- **Status:** Approved (pending user spec review)
- **Workflow:** Superpowers-primary (OpenSpec used for archival only)

---

## 1. Context

Lango currently depends on `google.golang.org/adk@v1.0.0` (upgraded 2026-04-04). Upstream has shipped three releases since: v1.1.0, v1.2.0, and v1.3.0. v1.3.0 is a capability-expansion release introducing bidirectional Live streaming, audio caching, transcription pipelines, streaming function tools, Vertex MemoryBank, and a full `adka2a/v2` rewrite (v1 surface is `Deprecated`).

In parallel, `internal/adk/` (~5,800 LoC over 16 files) has accumulated wrapper logic — some of which upstream now provides natively (ThoughtSignature propagation, Agent navigation helpers).

This spec captures the **Capability-First** integration approach approved by the user on 2026-05-23.

---

## 2. Goals & Non-Goals

### Goals
- Upgrade to `google.golang.org/adk@v1.3.0` in a single dependency bump on a dedicated branch (`feature/adk-v1.3`).
- Adopt capabilities that map to user value: Skill Toolset, Streaming Function Tools, Live API (TUI Cockpit voice mode), A2A v2.
- Add voice IN/OUT to all three channels (Telegram, Discord, Slack) via async round-trip pattern.
- Slim the wrapper where upstream now provides the same functionality.
- Hold to Lango's `[[change-boundary-discipline]]`: each track is independently revertable.

### Non-Goals
- Discord real-time voice channel integration (Pattern B / Track G) — deferred to a future cycle.
- Vertex AI MemoryBank — Lango's memory layer (pgvector + RunLedger) remains canonical.
- AgentEngine deployment — Vertex deploy is not on the roadmap.
- Eventarc / PubSub triggers — not aligned with current sovereignty axis.
- Multi-vendor STT/TTS — Gemini API single-vendor by user decision; abstraction is interface-only so a future swap is not blocked.

### Preservation Decisions
The following Lango-specific logic is intentionally kept (upstream has no replacement):
- `errors.go` substring-based cause classifier (16 cause classes)
- `agent.go` turn-limit / wrap-up budget / hallucination retry / `[REJECT]` re-route
- `budget.go` `modelWindowRegistry` (30 model prefixes)
- `session_service.go` auto-create-on-Get (deliberate ADK contract deviation, documented at L:126-131)
- `pii_model.go` PII redactor + secret scanner
- `context_model.go` 4-phase context engineering pipeline

## 4. Track Details

### Track 0 — ADK v1.0 → v1.3 single bump

**Approach:** one dependency bump on `feature/adk-v1.3`, not staged through v1.1 → v1.2 → v1.3.

**Files affected:**
- `go.mod` / `go.sum` — `google.golang.org/adk v1.3.0`; transitive bumps: `genai 1.40 → 1.57`, `a2a-go v0.3.10 → v0.3.15`, `a2a-go/v2 v2.3.1` (new), gRPC, OTel, cobra.
- `internal/adk/agent.go` — `agent.Agent` interface now requires `FindAgent(name string) Agent` and `FindSubAgent(name string) Agent`. Custom agent types must implement these (default walk recurses subagents).
- `internal/adk/state.go` — `model.LLMResponse` gained `InputTranscription`, `OutputTranscription`, `SessionResumptionHandle` fields. Add nil-safe reads; do not populate yet (Track E will).
- `internal/observability/*` — OTel attribute key changed: `gen_ai.usage.experimental.reasoning_tokens` → `gen_ai.usage.reasoning.output_tokens`. Update emitters and any dashboards that read this.

**Gate:**
1. `go build ./...` green
2. `go test ./...` green (entire suite, 140+ packages)
3. No new lint warnings

### Track A — Wrapper Slim-Down

**Goal:** delete Lango code that upstream now handles natively. Each deletion is a separate commit so it is independently revertable.

**Sub-tasks:**

A1. **ThoughtSignature handling — persistence vs streaming boundary (KEEP, do not remove).** Initial spec planned removal of `internal/adk/state.go:445-477` thought_signature round-trip because v1.3 added `internal/llminternal/stream_aggregator.go:40,107,143-146`. **Investigation result (2026-05-23):** the upstream change propagates `ThoughtSignature` *between Parts within a single LLM response stream* (streaming layer). Lango's `state.go` code propagates `ThoughtSignature` *between ADK runtime types and Lango's internal session storage* (persistence layer, for cross-session restoration). The two concerns are orthogonal. Removing Lango's code would break thought_signature continuity across session restarts and history reloads. **Decision: KEEP `state.go:445-477`.** Add an explanatory comment near that code referencing this finding. Also keep `state.go` consecutive same-role merging.

A2. **plugin.go re-evaluation.** `internal/adk/plugin.go` is marked spike-only with a stale parity-gap doc. ADK v1.x has a stable plugin API. Choice:
   - (a) Promote to production with a real wiring path through `internal/observability/` (`NewEventLoggingPlugin` for tool/event telemetry).
   - (b) Delete the file if `toolchain` middleware fully covers the use case.
   - Decision deferred to implementation: read v1.3 `plugin.Plugin` interface, compare to current toolchain hooks, then choose.

A3. **OTel attribute rename.** Update any consumer of `experimental.reasoning_tokens` to read `reasoning.output_tokens`. Note: dashboards outside the repo (Grafana, etc.) are out-of-scope but should be flagged in commit message.

**Gate:** all tests green; no regression in reasoning-token telemetry; Gemini multi-turn run produces correct thought_signature flow.

### Track B — Skill Toolset Adapter

**Goal:** expose `.claude/skills/` content to ADK agents via the v1.2 `tool/skilltoolset/` API.

**New files:**
- `internal/adk/skilltoolset.go` — thin wrapper around upstream `skilltoolset.New(ctx, Config{Source: skill.NewFileSystemSource(os.DirFS(dir))})`. Lango does NOT implement a custom `skill.Source`; the upstream filesystem source already covers our requirements.
- `internal/adk/skilltoolset_test.go` — 5 unit tests using `t.TempDir()` and in-memory SKILL.md fixtures (empty dir, nonexistent, file-not-dir, valid skill, empty parent).
- `assets/skills/example-skill/SKILL.md` — one demo skill with valid YAML frontmatter, proving the wiring works.
- `internal/adk/agent.go` — new `WithToolsets(...tool.Toolset)` option plumbing `o.toolsets` into `llmagent.Config.Toolsets`.
- `internal/config/types.go` — new `AgentConfig.SkillsDir string` field (default empty = disabled).
- `internal/orchestration/orchestrator.go` — new `Config.Toolsets []adk_tool.Toolset` field plumbed into the orchestrator's `llmagent.Config.Toolsets` (sub-agents do not receive).
- `internal/app/wiring.go` — builds the SkillToolset once when `cfg.Agent.SkillsDir` is set, then routes it to BOTH the single-agent path (`adk.WithToolsets`) and the multi-agent path (`orchCfg.Toolsets`).

**Wiring:**
- `internal/app/wiring.go` — register `SkillToolset` when agent mode has skill access. `tool/skilltoolset/toolset.go:Config{Source, Name, SystemInstruction}`.
- The three skill tools (`load_skill`, `list_skill_resources`, `load_skill_resource`) become available through normal ToolRegistry routing.

**Source mapping decision:**
- Primary skill source for Track B: `assets/skills/` (Lango-shipped skill bundles with valid YAML frontmatter per agentskills.io).
- `.claude/skills/` migration is DEFERRED. Existing files mix Claude-Code-specific frontmatter (with `compatibility`, `metadata` fields) and bare markdown. A clean migration requires deciding which Claude-Code-specific fields to keep/strip per agentskills.io and verifying each skill is agent-runtime-relevant. Out of Track B scope.

**Gate:** an agent can call `load_skill("openspec-apply-change")` and receive its markdown body. Round-trip test asserts content equality.

### Track C — Streaming Function Tools

**Goal:** tool authors can yield partial chunks via `iter.Seq2[string, error]`. The non-live UI rendering of partial chunks is deferred to Track E (Live API) — see "Scope note" below.

**New types:**
```go
// internal/agent/runtime.go
type StreamingToolHandler func(ctx context.Context, params map[string]interface{}) iter.Seq2[string, error]

type Tool struct {
    ...
    StreamingHandler StreamingToolHandler // optional; nil = non-streaming
}
```

**Adapter:**
- `internal/adk/tools.go` — `AdaptStreamingTool(t *agent.Tool) (tool.Tool, error)`. When `t.StreamingHandler != nil`, routes through `functiontool.NewStreaming[map[string]any]`; else falls back to `functiontool.New`. Per-call timeout and agent-name context injection apply to both paths.

**Backward compatibility:** non-streaming tools are unaffected; `StreamingHandler` is nil-default.

**Scope note (non-live aggregation):**
ADK v1.3 `internal/llminternal/base_flow.go:1106-1117` collects all chunks via `strings.Builder` and returns a single concatenated string in non-live runs. So in this track, `internal/turnrunner/*` and `internal/cockpit/*` see no intermediate events to render — adding `ToolPartialChunk` events here would have no upstream source. The chunk-surfacing pipe is built in Track E, where `liveSessionImpl` delivers each chunk to `liveSess.Send` as it is produced.

**Gate:** `AdaptStreamingTool` compiles, accepts a `StreamingHandler`, and returns a valid `tool.Tool`. The fallback path (non-streaming) still works. Unit tests cover both branches.

### Track D — A2A v2 Immediate Migration

**Goal:** switch outbound A2A client (`internal/a2a/remote.go`) from v1 `agent/remoteagent` to v2 `agent/remoteagent/v2`. Inbound surface in `internal/a2a/server.go` is a custom AgentCard JSON server (not an ADK adka2a executor) — out of scope for Track D.

**Files affected:**
- `internal/a2a/remote.go` — import `agent/remoteagent/v2`. Replace removed-in-v2 `A2AConfig.AgentCardSource string` with `AgentCardProvider: remoteagent.NewAgentCardProvider(url)` (lazy URL/file resolver).
- `internal/a2a/remote_test.go` — same import switch; signature-compatible.

**Files NOT modified (intentional):**
- `internal/a2a/server.go` and its tests — Lango's custom AgentCard JSON server with P2P/pricing/ZK extensions. It serves `/.well-known/agent.json` using its own `AgentCard` struct and imports `google.golang.org/adk/agent` only for the `agent.Agent` interface. No ADK executor migration needed.

**`a2a-go/v2 v2.3.1`** entered the module graph as a transitive `// indirect` dependency during Track 0's `go.mod` bump. Track D does not promote it to direct.

**Gate:** all tests in `./internal/a2a/...` pass; no v1 `agent/remoteagent` import remains in Lango source; whole-tree test suite matches baseline.

### Track E — Live API Plumbing (Phase 1: framework-agnostic state machine)

**Goal:** ship the Live API plumbing — `internal/live/` Session wrapper + `VoiceMode` state machine + `internal/turnrunner/live.go` `RunnerLiveExecutor`. UI-framework-agnostic. Bubbletea cockpit integration is **deferred to Phase 1.5**. Audio I/O is **deferred to Phase 2**.

**New files (Phase 1):**

- `internal/live/audio.go` — `AudioSink` / `AudioSource` interfaces + `NoOpSink` / `NoOpSource` defaults.
- `internal/live/session.go` — `Session` wrapper around `runner.Runner.RunLive`.
- `internal/live/voicemode.go` — `VoiceMode` state machine + local `LiveExecutor` interface (placed in `live` to avoid the import cycle that `internal/turnrunner` would create).
- `internal/turnrunner/live.go` — `RunnerLiveExecutor` default impl satisfying `live.LiveExecutor`.
- Tests: 5 in `session_test.go`, 6 in `voicemode_test.go`.

**Phase 1.5 (deferred — separate change):**
- `internal/cli/cockpit/keymap.go` — `Ctrl+V` binding.
- `internal/cli/cockpit/cockpit.go` — `tea.Cmd` wrapping `VoiceMode.Toggle`; goroutine bridging `Session.Events()` → `program.Send(liveEventMsg)`; header indicator.

**Phase 2 (deferred — separate spec):**
- malgo/portaudio CGO bindings; PCM resampling; `genai.ModalityAudio`; `gemini-3.1-flash-live-preview`.

**Gate (Phase 1):** `internal/live/` and `internal/turnrunner/live.go` compile; 11 unit tests pass; cockpit files untouched.

### Track F — Channel Voice Infrastructure (Phase 1)

**Goal — Phase 1 (this track):** ship the `internal/voice/` package — SpeechToText / TextToSpeech interfaces, Gemini-backed STT, NoOp defaults, sentinel errors, and config plumbing. Per-channel integration (Telegram/Discord/Slack download → STT → inject; outbound TTS → sendVoice) is **deferred to Phase 2** because each channel's bot API has different voice capabilities and warrants per-channel design.

**New files (Phase 1):**
- `internal/voice/types.go` — `Audio`, `STTOptions`, `TTSOptions`, sentinel errors.
- `internal/voice/stt.go` — `SpeechToText` interface.

- `internal/voice/noop.go` — `NoOpSTT` / `NoOpTTS`.
- `internal/voice/gemini_provider.go` — Gemini STT via `GenerateContent`. TTS is gated on `TTSModel` config — Phase 1 returns `ErrTTSNotConfigured` for now.
- `internal/voice/voice_test.go` — 8 unit tests.

**Modified files:**
- `internal/config/types.go` — `VoiceConfig` + `VoiceChannelConfig` + `VoiceCostGuard` structs; new `Voice VoiceConfig` field on top-level Config.

**Phase 2 (deferred — separate change):**
- Per-channel inbound: Telegram `getFile` → audio download → `voice.SpeechToText.Transcribe` → inject as text message.
- Per-channel outbound: optional `voice.TextToSpeech.Synthesize` → `sendVoice` / file upload.
- Real Gemini TTS implementation (currently a stub returning `ErrTTSNotConfigured`).

**Gate (Phase 1):** `internal/voice/` compiles; 8 unit tests pass; `VoiceConfig` is present in top-level config; no channel adapters modified.

## 5. Data Flow Diagrams

### Cockpit Voice Mode (Track E)
```
[mic] → malgo capture → PCM 16k mono
      → resample 24k
      → genai.Blob{audio/pcm}
      → LiveSession.Send(LiveRequest{RealtimeInput: blob})
                          ↓
                  Runner.RunLive
                          ↓
              iter.Seq2[*session.Event, error]
                          ↓
            ┌─────────────┼─────────────┐
            ↓             ↓             ↓
       transcription   audio out    tool calls
        (UI pane)      → speaker    → streaming
                                       chunks
                                       (Track C)
```

### Channel Voice Round-trip (Track F)
```
[Telegram voice msg]
      → getFile → OGG download
      → voice.STT (Gemini)
      → text
      → turnrunner.Run (normal, NOT RunLive)
      → response text
      → voice.TTS (Gemini)
      → OGG/Opus
      → sendVoice
      → [user receives]
```

## 7. Risks & Mitigations

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|-----------|
| ADK v1.3 transitive deps break build | M | H | Track 0 on isolated branch; revert in one step if needed |
| `Agent.FindAgent/FindSubAgent` interface change cascades | M | M | Provide default implementations on all custom Agent types in Track 0 |
| ThoughtSignature regression after Track A removal | M | M | Regression test before deletion; keep code one commit removed for easy revert |
| A2A v2 incompatible with existing peers | L | M | Outbound-only migration: Lango is an A2A *client*, not an inbound adka2a executor. v2 NewA2A still accepts arbitrary agent cards; peers untouched. |
| malgo audio I/O unstable on Linux | M | M | Fallback to portaudio; CI tests on macOS + Ubuntu |
| Gemini Live API rate limits | M | M | Cost guard config; queue with backoff |
| Voice STT/TTS cost runaway | H | M | Per-channel enable flag default false; daily second cap |
| Voice messages contain sensitive PII | M | H | Run PII redactor on STT output BEFORE turnrunner; `SaveLiveBlob: false` default |
| Skill Toolset frontmatter mismatch with `.claude/skills/` format | M | L | Adapter normalizes frontmatter; tests cover both shapes |

## 8. Rollout

1. **Branch:** `feature/adk-v1.3` (already created).
2. **Per-track commits:** each track's gate must be green before merging into the feature branch's working state.
3. **No merge to `dev`** until Tracks 0-F all green and demos pass.
4. **Documentation updates** (mandatory per `.claude/CLAUDE.md`): README.md, CLI `--help`, TUI keybinding docs, voice config docs, skill toolset usage.
5. **OpenSpec archival** (record-keeping per new workflow rule):
   - One archived OpenSpec change per merged track.
   - Generated post-implementation via `opsx:new` → `opsx:ff` → `opsx:archive`.

- **Vertex MemoryBank backend** — Lango memory layer (pgvector + RunLedger) remains canonical.
- **AgentEngine deployment surface** — no Vertex deploy roadmap.
- **Eventarc / PubSub triggers** — not aligned with sovereignty axis.
- **Multi-vendor STT/TTS** — Gemini single-vendor per user decision.
