# ADK v1.3 Track 0 — Dependency Bump Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade `google.golang.org/adk` from v1.0.0 to v1.3.0 in a single dependency bump on `feature/adk-v1.3`, with build and test green across all packages.

**Architecture:** Single `go.mod` version change + transitive dependency reconciliation. Adapt to v1.1's `Agent.FindAgent`/`FindSubAgent` (no Lango custom impls, transparent), v1.3's new `model.LLMResponse` transcription/resumption fields (nil-safe reads only, no population), and the OTel `gen_ai.usage.reasoning.output_tokens` rename (currently not emitted by Lango — no consumer change required, but verify). Tracks A–F are separate plans that depend on this one landing.

**Tech Stack:** Go 1.23+, `google.golang.org/adk` v1.3.0, `google.golang.org/genai` v1.57+, `github.com/a2aproject/a2a-go` v0.3.15, `github.com/a2aproject/a2a-go/v2` v2.3.1 (new), gRPC v1.81.0, OTel v1.43.

**Spec reference:** `internal-docs/superpowers/specs/2026-05-23-adk-v1.3-capability-first-design.md` §4 Track 0.

**Branch:** `feature/adk-v1.3` (already created).

**Pre-flight context the engineer needs:**
- This project uses OpenSpec for archival only as of 2026-05-23. Superpowers is the primary workflow. See `~/.claude/.../memory/feedback_superpowers_primary_openspec_record.md`.
- Lango wraps ADK heavily in `internal/adk/` but does NOT define any custom `adkagent.Agent` implementations — all agents come from upstream factories (`llmagent.New`, `remoteagent.NewA2A`). So the v1.1 `Agent.FindAgent`/`FindSubAgent` interface additions are transparent. (Import alias convention in Lango: majority style is `adkagent`/`adktool`; the plan uses this convention.)
- The user commits manually (memory: `[[user-commits-manually]]`). DO NOT run `git commit` or `git push`. After each task, propose a commit message and let the user run the commit themselves.
- The user requires Korean for chat but English for all code, comments, tests, and docs (memory: `.claude/CLAUDE.md`).
- Mandatory: after any code change, run `go build ./...` and `go test ./...` (memory: `.claude/CLAUDE.md` Build & Test rule).

## Task 3: Add the v1.3 surface smoke test

**Files:**
- Create: `internal/adk/v1_3_smoke_test.go`

This test does not exercise behavior — it asserts that the new v1.3 packages and types are reachable. It serves as a tripwire: any future accidental downgrade or vendor-vendor drift will fail this test immediately.

- [ ] **Step 1: Write the smoke test file**

Create `internal/adk/v1_3_smoke_test.go`:

```go
package adk

import (
	"testing"

	adkagent "google.golang.org/adk/agent"
	"google.golang.org/adk/model"
	"google.golang.org/adk/tool/functiontool"
	"google.golang.org/adk/tool/skilltoolset"
)

// TestADKv13SurfaceReachable asserts that the v1.3 API surface we plan to
// adopt in Tracks A-F compiles and is importable. It does NOT exercise
// behavior — it is a tripwire against accidental downgrade.
func TestADKv13SurfaceReachable(t *testing.T) {
	// v1.1+: Agent interface includes FindAgent/FindSubAgent (compile-time check).
	var _ interface {
		FindAgent(name string) adkagent.Agent
		FindSubAgent(name string) adkagent.Agent
	} = (adkagent.Agent)(nil)

	// v1.3: model.LLMResponse has transcription fields (compile-time field access).
	var resp model.LLMResponse
	_ = resp.InputTranscription
	_ = resp.OutputTranscription
	_ = resp.SessionResumptionHandle

	// v1.3: streaming function tools package is importable.
	_ = functiontool.Config{}

	// v1.2+: skill toolset package is importable.
	_ = skilltoolset.Config{}

	// v1.3: live session interface is reachable (used in Track E).
	var _ adkagent.LiveSession = (adkagent.LiveSession)(nil)
}
```

- [ ] **Step 2: Run the smoke test**

Run:
```bash
go test ./internal/adk/ -run TestADKv13SurfaceReachable -v
```

Expected: `PASS`. If it fails to compile:
- Missing field on `model.LLMResponse`: the v1.3 upgrade is incomplete — check `go.mod` and `go.sum`.
- Missing package `tool/skilltoolset`: same — upgrade is incomplete.

- [ ] **Step 3: Run the entire test suite once more**

Run:
```bash

```

Expected: still all green. The smoke test should add one `ok` line to `internal/adk`.

- [ ] **Step 4: Propose commit message**

## Task 4: Verify downstream consumers compile

**Files:** verification only.

The transitive bump of `genai v1.40 → v1.57` is the largest API surface change in the upgrade. Verify that Lango code that uses `genai` types directly still compiles. From the earlier grep, the main hotspots are:

- `internal/adk/state.go`
- `internal/adk/model.go`
- `internal/adk/context_model.go`
- `internal/turnrunner/runner.go`

These are already covered by `go build ./...` in Task 2. This task adds explicit narrow tests to catch silent type-compatibility hazards.

- [ ] **Step 1: Run targeted vet on hotspot packages**

Run:
```bash
go vet ./internal/adk/... ./internal/turnrunner/... ./internal/a2a/...
```

Expected: no warnings. If `go vet` reports anything:
- Composite literal warnings on `model.LLMResponse` (positional init): rewrite as keyed init.
- Struct tag warnings: fix in place.

- [ ] **Step 2: Run targeted tests on hotspots**

Run:
```bash
go test -count=1 ./internal/adk/... ./internal/turnrunner/... ./internal/a2a/...
```

Expected: all pass. `-count=1` defeats the test cache so we catch any flakiness from new transitive deps.

- [ ] **Step 3: Spot-check `internal/adk/model.go` for LLMResponse composite literals**

Run:
```bash
grep -n "model.LLMResponse{" internal/adk/model.go internal/adk/state.go
```

Expected: each match uses keyed field init (`model.LLMResponse{Content: ..., Done: ..., ...}`), not positional (`model.LLMResponse{c, true, ...}`). Positional init would have broken when the new v1.3 transcription fields were appended. Spot-check expectation as of 2026-05-23: all four call sites (one in `state.go`, three in `model.go`) are already keyed — this step should be a verification no-op.

If a positional literal IS found, STOP and surface the file:line to the user — converting it to keyed init is out of scope for Track 0 (Track 0 promises `state.go`/`model.go` are read-only). File a follow-up task; do not edit in this track.

Run:
```bash
go build ./... && go test ./... 2>&1 | tail -10
```

Expected: clean build, all tests pass.
